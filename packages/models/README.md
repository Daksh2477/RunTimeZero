# @rtz/models

Four models. **Owner: Mahit (training) · Chetan (data generation).**

## The boundary, before anything else

**No model decides what gets credited.** That is done by the hard rule in `docs/DECISIONS.md` #5:

```
mintable = min(claimedUptake, independentEstimate)
require(claimedUptake <= physicsCeiling)
```

Arithmetic only, no fitted parameters, recomputable by a judge with a calculator.

Models do two other jobs: they make the platform **useful to the operator**, and they catch
**sophisticated** fraud that the hard rule cannot — a claim that stays under the ceiling but carries
a suspicious signature over time.

Put plainly: *the hard rule catches impossible claims. The model catches clever ones. Neither is
allowed to do the other's job.*

## The models

### 1. Crash early-warning — `crash_classifier`

Predicts culture collapse 24–48 h ahead from the recent telemetry window.

- **Input:** 48 h of pH, DO, temperature, optical density, plus their first differences
- **Output:** P(crash within 48 h), and the dominant contributing factor
- **Why it's legitimate:** this is the operator's actual daily pain and the reason they open the app
  at all. Nothing about crediting depends on it.
- **Training data:** generated by the twin. We can produce unlimited labelled crashes — nitrogen
  starvation, contamination, pump failure, thermal shock — which is exactly the situation where
  synthetic training data is defensible rather than a cop-out.

### 2. Divergence pattern classifier — `divergence_classifier`

Given a sequence of divergence checks, distinguishes **noise** from **drift** from **systematic
overstatement**.

- **Input:** last 12 divergence values, their signs, magnitudes, and the width of each error band
- **Output:** `noise | drift | systematic`, with confidence
- **Why it's legitimate and interesting:** the hard rule already refuses anything above the physics
  ceiling. A careful fraudster stays *just under* it and overstates by 8% forever. Each individual
  window looks fine. The pattern does not. This is the model that earns its place.
- **Constraint:** it may only influence the `watch`/`flagged` **verdict**, never `creditableCo2Kg`.
  That number stays arithmetic.

### 3. Yield residual corrector — `yield_residual`

Physics predicts the baseline; the model learns the site-specific residual.

- **Input:** physics forecast, weather forecast, site features, recent residual history
- **Output:** corrected yield forecast for the next 72 h
- **Why it's legitimate:** this is standard practice in energy forecasting — physics for the bound,
  ML for the correction. A pond systematically under-performs its clear-sky ceiling because of
  shading, strain, fouling and operator habits. Those are learnable; the ceiling is not.
- **Hard constraint:** the corrector may only ever **lower** the forecast against the physics
  ceiling, never raise a claim above it.

### 4. Imagery calibration — `ndci_biomass`

Maps chlorophyll index to biomass density, with a prediction interval.

- **Input:** NDCI (or drone green-channel index), pond depth, solar zenith, water temperature
- **Output:** biomass g/L with a **prediction interval**, not a point estimate
- **Why the interval matters more than the value:** validated NDCI carries a mean absolute error
  factor near 2.4. A point estimate would be dishonest. The interval is what the reconciliation
  engine consumes, and a wide interval simply means we credit less.

## How they run

Trained offline in Python, exported to ONNX, inference in Node via `onnxruntime-node`.

Training is a **dev-time** dependency only — the running platform is still TypeScript with no Python
in the request path. Simple fits (`ndci_biomass`) ship as JSON coefficients with no runtime at all.

```
packages/models/
├── train/           python — one script per model, deterministic seeds
├── data/            generated datasets (gitignored, regenerate with make_dataset.py)
├── artifacts/       committed .onnx and .json — the things the API actually loads
└── src/             TypeScript inference wrappers
```

```bash
python train/make_dataset.py --model crash --n 20000 --seed 42
python train/train_crash.py
npm run models:verify        # asserts artifacts load and produce expected outputs
```

## Rules

1. **Every training run is seeded.** An unreproducible model is not evidence of anything.
2. **Every model ships with its metrics** in `artifacts/<model>.meta.json` — dataset size, seed,
   train/test split, and the confusion matrix or error distribution. If a judge asks "how good is
   it?", the answer is a file, not a shrug.
3. **No model touches `creditableCo2Kg`.** If you find yourself importing a model into
   `apps/api/src/reconcile/engine.ts`, stop and re-read decision #5.
4. **Report honest numbers.** A crash classifier at 0.78 AUC that we describe as 0.78 is worth more
   than one we claim is 0.95. Judges ask follow-up questions.
